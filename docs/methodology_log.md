## Step 3 — Forecasting Feature Engineering

### Status
Completed

### Objective
Transform the prepared hourly UCI dataset into a feature table suitable for one-hour-ahead energy-consumption forecasting.

### Input
data/processed/uci_hourly.csv

### Actions
- Sorted the hourly data chronologically.
- Extracted hour of day, day of week, and month from the timestamp.
- Created a weekend indicator.
- Encoded hour, day of week, and month using sine and cosine transformations.
- Created prototype heating and cooling indicators using outdoor temperature.
- Created a one-hour lag of appliance energy consumption.
- Created a 24-hour lag of appliance energy consumption.
- Created a rolling mean of the previous 24 hours of appliance energy consumption.
- Created a rolling mean of the previous 168 hours (seven days) of appliance energy consumption.
- Shifted the rolling calculations by one observation so that the current hour was excluded from historical rolling averages.
- Created the one-hour-ahead target by shifting appliance energy consumption backward by one row.
- Removed observations lacking sufficient historical data for lagged or rolling predictors.
- Removed the final observation where a future one-hour target could not be constructed.
- Verified chronological ordering, required features, duplicate timestamps, and missing values in required forecasting fields.

### Methodological Rationale
The primary modeling task is a one-hour-ahead forecast. Historical energy variables were therefore constructed so that each row contains information available before the future target hour.

Lagged values capture short-term and daily persistence in energy consumption. Rolling averages represent recent baseline behavior over one-day and seven-day periods.

Cyclical sine and cosine transformations were used for hour, day of week, and month so that periodic variables preserve their circular relationships. For example, hour 23 and hour 0 are represented as temporally adjacent rather than numerically distant.

Rolling statistics were calculated after shifting the target series by one hour. This prevents the current observation from being incorporated into historical rolling averages and reduces the risk of temporal information leakage.

The forecasting target represents appliance energy consumption during the following hour.

### Prototype Temperature Indicators
The initial UCI prototype uses an outdoor-temperature threshold below 18°C for the heating indicator and above 22°C for the cooling indicator. These values are configurable implementation assumptions because the project outline does not prescribe specific thresholds.

## Step 5 — Baseline Forecasting Models

### Status
Completed

### Objective
Establish simple reference models against which the project's more complex tree-based ensemble regressors can later be evaluated.

### Inputs
- data/processed/uci_train.csv
- data/processed/uci_validation.csv

The final test partition was not used during this stage.

### Models
Three initial baseline forecasting approaches were evaluated:

1. Seasonal-naive forecasting
2. Linear Regression
3. Lasso Regression

### Seasonal-Naive Baseline
The seasonal-naive model predicts that consumption during the forecast hour will resemble consumption during the same hour on the previous day.

Because each row at time t predicts consumption at t+1, the corresponding hour on the previous day occurs at t-23. The previously constructed seasonal_naive_24h feature was therefore used directly as the seasonal-naive prediction.

### Linear Regression
Linear Regression was used as an interpretable statistical baseline.

The model used current observed appliance consumption, environmental measurements, cyclical temporal features, lagged consumption values, rolling consumption averages, weekend status, and prototype heating/cooling indicators where applicable.

Raw hour, day-of-week, and month variables were excluded because their cyclical sine and cosine representations were already included.

### Lasso Regression
Lasso Regression was used as a regularized linear baseline.

An initial regularization parameter of alpha = 0.1 was used for the untuned prototype. This value is not interpreted as optimal and will be revisited during hyperparameter tuning.

### Preprocessing
Linear Regression and Lasso were implemented with Scikit-Learn pipelines.

For numerical predictors:
- missing values, if encountered, were median-imputed;
- variables were standardized using StandardScaler;
- all preprocessing transformations were fit using training data only;
- the fitted transformations were then applied to validation data.

This structure reduces the risk of information from the validation period influencing model preprocessing.

### Evaluation
All baseline models were evaluated on the chronological validation partition.

Metrics included:

- Mean Absolute Error (MAE)
- Coefficient of Variation of Root Mean Squared Error (CVRMSE)
- Mean Absolute Percentage Error (MAPE)

CVRMSE was defined as:

CVRMSE = RMSE / mean(actual consumption) × 100

MAPE excluded observations where the actual target equaled zero because percentage error is undefined for zero-valued actual observations. The number of observations included in the MAPE calculation was recorded as MAPE_n.

### Test-Set Policy
The final test partition remained untouched during baseline model development and comparison.

### Output
outputs/tables/uci_baseline_validation_metrics.csv

This difference illustrates why model performance is evaluated using multiple complementary metrics rather than a single error measure.

## Step 6 — Initial Tree-Based Ensemble Models

### Status
Completed

### Objective
Evaluate whether nonlinear tree-based ensemble regressors improve one-hour-ahead UCI forecasting performance relative to the previously established baseline models before hyperparameter tuning.

### Inputs
- data/processed/uci_train.csv
- data/processed/uci_validation.csv

The final test partition remained unused.

### Models
Three tree-based regression models were trained:

1. Random Forest Regressor
2. Extra Trees Regressor
3. Gradient Boosting Regressor

### Initial Model Configuration
Random Forest and Extra Trees were initialized with 200 estimators and the shared project random state.

Gradient Boosting was initially trained using its standard Scikit-Learn configuration with the shared project random state.

These configurations represent untuned prototype models and are not interpreted as optimal hyperparameter settings.

### Predictors
The same underlying predictor set used by the linear baseline models was supplied to the tree-based models, excluding:
- the timestamp;
- the one-hour-ahead target;
- the dedicated seasonal-naive benchmark feature;
- raw hour, day-of-week, and month variables whose cyclical sine/cosine counterparts were already available.

### Preprocessing
Tree-based models were implemented with Scikit-Learn pipelines.

Missing numerical predictor values, if encountered, were median-imputed.

Numerical standardization was not applied because threshold-based tree models do not generally require feature scaling.

### Evaluation
Each model was trained on the same chronological training partition and evaluated on the same fixed validation partition used for the baseline models.

Performance was measured using:
- MAE
- CVRMSE
- MAPE

Using the same validation period allows direct comparison between baseline and tree-based model performance.

### Test-Set Policy
The final chronological test partition remained untouched.

## Step 10 — K-Means Consumption-Pattern Clustering

### Status
Completed

### Objective
Use unsupervised K-Means clustering to identify recurring hourly energy-consumption and environmental operating patterns within the UCI prototype dataset.

### Input
data/processed/uci_hourly.csv

### Analysis Scope
K-Means clustering was treated as a descriptive unsupervised analysis rather than a forecasting model.

The full prepared hourly UCI dataset was therefore used for cluster-pattern discovery rather than applying the supervised train-validation-test partitioning framework.

### Clustering Variables
The following variables were selected:

- appliance energy consumption;
- lighting energy consumption;
- outdoor temperature;
- outdoor relative humidity;
- wind speed;
- cyclical hour-of-day sine component;
- cyclical hour-of-day cosine component;
- weekend indicator.

The feature set was intentionally restricted to interpretable energy, outdoor-weather, and temporal characteristics.

Lagged consumption, rolling forecasting variables, forecast targets, and the broader collection of correlated indoor environmental sensors were not used for clustering.

### Temporal Feature Engineering
Hour of day was represented using sine and cosine transformations so that the cyclical relationship between late-night and early-morning hours was preserved.

A binary weekend indicator was also included.

### Scaling
All clustering variables were standardized using StandardScaler prior to fitting K-Means.

Scaling was necessary because K-Means uses distance-based assignments and the input variables are measured on substantially different numerical scales.

Cluster profiles were subsequently summarized using the original, unstandardized variables to preserve interpretability.

### Cluster-Count Selection
Candidate K-Means solutions were evaluated for cluster counts from k = 2 through k = 8.

For each candidate solution:
- within-cluster inertia was recorded;
- silhouette score was calculated.

The final cluster count was selected using the highest silhouette score.

### Final K-Means Model
The selected K-Means model used:
- the selected number of clusters;
- random_state = 42;
- n_init = 20.

### Cluster Interpretation
Cluster profiles were created using mean original-scale values for:
- appliance consumption;
- lighting consumption;
- outdoor temperature;
- outdoor relative humidity;
- wind speed;
- hour of day;
- weekend status.

The number and percentage of hourly observations assigned to each cluster were also calculated.

Cluster labels are interpreted as descriptive pattern identifiers and do not inherently represent ordered categories.

### Outputs
- outputs/tables/uci_kmeans_cluster_selection.csv
- outputs/tables/uci_kmeans_cluster_profiles.csv
- outputs/tables/uci_clustered_hourly.csv
- outputs/figures/uci_kmeans_cluster_selection.png
- outputs/figures/uci_kmeans_consumption_vs_temperature.png
- outputs/figures/uci_kmeans_cluster_sizes.png

### Next Step
Review and interpret the resulting clusters and formally close the UCI prototype before adapting the tested workflow to the project's primary datasets.
